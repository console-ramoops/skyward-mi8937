# Mi-Thorium mi8937_4_19 port

## Current public release

[0.2.0 (Mi8937_4_19)](https://github.com/console-ramoops/skyward-mi8937/releases/tag/v0.2.0-mi8937-4_19),
updated 2026-11-12. Download the
[public IMG](https://github.com/console-ramoops/skyward-mi8937/releases/download/v0.2.0-mi8937-4_19/Skyward-0.2.0-Mi8937_4_19.img)
and its [SHA-256 file](https://github.com/console-ramoops/skyward-mi8937/releases/download/v0.2.0-mi8937-4_19/Skyward-0.2.0-Mi8937_4_19.img.sha256)
directly from the release Assets.

Image SHA-256:
`d3e64c39bf93b8b5df9c544faa69621c2aa1f07691e0d3c1308e1c221924414f`.
The public image uses the original 4.19.312 kernel.

This port targets the unified Mi-Thorium MSM8917/MSM8937/MSM8940 recovery
with the 4.19 kernel. It uses the kernel's `/sys/xiaomi-msm8937-mach` identity
and the framebuffer's actual dimensions, so the image is not fixed to Redmi
4X/santoni.

The supplied base image has SHA-256
`fec32362b887b122c1af54b9c82ede89f98240e871b9c4c5cde61ad08cfc1239`.
It has boot header v0, 2048-byte pages, kernel-appended DTBs, an LZMA-alone
ramdisk and no AVB footer. Packing preserves that layout and the base's init,
adbd, loader, libraries, SELinux files and device-selection scripts. It replaces
TWRP with Skyward, removes `twres`, and includes a MiSans variable-font subset
covering the UI strings and GB2312. Both the 64 MiB recovery partition and the
20 MiB compressed ramdisk limit are checked before writing the output.

The base selects its FBE-v2/inlinecrypt data table at boot, with `oem` mounted
at `/metadata`. This port retains those encryption flags and keys. System and
vendor use the runtime layout: physical `system`/`cust` on a non-dynamic ROM,
or logical partitions over Mi-Thorium's retrofit `system` and `cust` devices.
The ramdisk bundles Qualcomm's keystore and gatekeeper modules as
`keystore.default.so` and `gatekeeper.default.so`, together with qseecomd
and its libraries. The port loads these recovery files directly, without
mounting the installed vendor partition. Trusted applications still come
from the modem firmware partition.

Touch uses the kernel's input drivers directly, including Back, Home and
Menu events from the touchscreen. Back leaves a page, Home returns to the
main page, and Menu opens Settings. Home respects the same write-in-progress
and unsaved-file checks as Back. These three keys pulse the motor when
vibration is enabled. Vibration uses the kernel's timed driver at
`/sys/class/leds/vibrator`; the strength slider controls pulse duration.
Wi-Fi has no unified configuration yet. A/B slot switching,
A/B OTA payload installation and Skyward's init_boot-based dual boot are
unavailable on these single-slot devices. Script-based ROM ZIP installation,
image flashing, storage operations, backups and USB use the imported legacy
device support.

The port defaults to English until a language is explicitly chosen, shows
maintainer `alpha269` beside the recovery version, and uses 16 dp horizontal
status bar insets. Its UI uses 267 DPI and every page can scroll when its
content is taller than the panel. Indian Standard Time (IST, `Asia/Kolkata`) and Western
Indonesia Time (WIB, `Asia/Jakarta`) are available in Settings.

Ordinary recovery boots start opening data in the background, using the
same decryption worker as the Data page. User files protected by a screen
lock still require that credential on the Data page. Explicit install,
wipe and fastboot requests retain their own data-opening order.

MTP downloads use packet-aligned 16 KiB chunks. The Redmi 4X's Qualcomm
ci13xxx USB driver rejects larger bulk IN requests with `EINVAL`; this
previously allowed browsing storage while every large download failed.
Short write completions are finished before moving to the next chunk.

The removable microSD slot is detected as `mmcblk1` and mounted read-write
at `/sdcard1`, trying its largest partition first (the base device tree names
`mmcblk1p1`, with `mmcblk1p4` as a fallback). Insertion and removal are
noticed while recovery is running. The Install page opens the configured card
in File manager. MTP offers the mounted card as a separate
storage, including while internal storage is locked. A recovery process
restart reuses the card's existing mount instead of repeatedly failing with
`EBUSY`.

Background page drawing rebuilds a page when updated readings change its
height, preventing incompatible canvas bands from aborting the recovery.
Any further Rust panic is written to the kernel log as well as stderr.

## Build locally

Download and extract the
[matching release sources](https://github.com/console-ramoops/skyward-mi8937/releases/download/v0.2.0-mi8937-4_19/Skyward-0.2.0-mi8937-4_19-20261112-source.tar.gz).
The archive contains a `skyward/` directory; run the commands below there.
The snapshot contains the implementation used for this release, including
the drawing and microSD MTP fixes.

On a Linux computer, install Rust, the `aarch64-linux-android` target, Android
NDK r29 and cargo-ndk. Set `ANDROID_NDK_HOME` to the NDK directory. Install
the font tool and run:

```sh
python3 -m pip install fonttools==4.68.0
CARGO_BUILD_JOBS=1 tools/build-mi8937-4.19.sh /path/to/twrp-4.19/recovery.img out/skyward-mi8937_4_19.img
python3 tools/verify-mi8937-4.19.py /path/to/twrp-4.19/recovery.img out/skyward-mi8937_4_19.img
```

The script also supports native arm64 Termux builds with `rust`, `clang`,
`make`, `pkg-config`, `python` and `patchelf` installed. It removes Termux's
library search path from the recovery binary before packing it.
Compilation defaults to one job to limit memory use on Termux. Set
`CARGO_BUILD_JOBS` to override that default on a larger build host.

The **Build Mi-Thorium mi8937_4_19** GitHub Actions workflow takes an HTTPS
base-image URL and its SHA-256, then builds and uploads a ZIP. This device is
excluded from the stock-firmware matrix because its base is a custom recovery
provided separately.

## Boot and USB

On a device whose unlocked bootloader supports booting an image from RAM, use:

```sh
fastboot boot Skyward-0.2.0-Mi8937_4_19.img
```

The startup wrapper records output in `/tmp/recovery.log`; the application's
detailed log is `/skyward/run/recovery.log`. Once adb connects, collect both
files and `adb shell dmesg` to diagnose display, input, USB or encryption
issues.

Enable **Settings → File transfer** and reconnect USB. MTP offers unlocked
internal storage and the mounted microSD card as separate storages. The
microSD remains available while internal storage is locked.

The screen timeout is configurable in Settings. Back, Home and Menu operate
the pages, and the vibration setting controls their feedback pulses.
